## 分析总结

### 1. 什么是 BFC？
BFC（Block Formatting Context）是块级格式化上下文，是一个独立的渲染区域。主要特性：
- 可以包含浮动的子元素（解决浮动导致的高度塌陷）
- 阻止 margin 合并
- 隔离内外元素，互不影响

### 2. 当前是否产生了 BFC？
没有。`.par` 中所有创建 BFC 的属性都被注释掉了，所以当前没有创建 BFC。

### 3. 为什么 `.par` 高度塌陷了？
原因：子元素使用了 `position: absolute;`
- 绝对定位的元素会脱离文档流
- 脱离文档流的元素不占据空间
- 父元素无法包含脱离文档流的子元素高度
- 因此 `.par` 的高度变成了 0（只有边框，没有内容高度）

重要：BFC 对绝对定位的子元素无效
- 绝对定位是相对于最近的定位父元素（position 不为 static）定位的
- 不是相对于 BFC 定位的
- 所以创建 BFC 无法解决绝对定位导致的高度塌陷

### 4. 怎么处理？
已提供 4 种解决方案（在代码注释中）：
1. 方案1：给父元素设置 `position: relative` 并设置明确高度
2. 方案2：移除子元素的绝对定位，改用浮动或其他布局
3. 方案3：如果必须使用绝对定位，给父元素设置 `min-height`
4. 方案4：使用 flex 布局（需要移除绝对定位）

## 核心问题

即使 `.par` 使用 `position: fixed` 创建了 BFC，父元素仍未撑开，原因是：

### BFC 的作用范围

- BFC 可以解决浮动元素导致的高度塌陷
- BFC 无法解决绝对定位元素导致的高度塌陷

### 为什么绝对定位不行？

1. 绝对定位的元素完全脱离文档流，不参与父元素的高度计算
2. 绝对定位是相对于最近的定位父元素（position 不为 static）定位，不是相对于 BFC
3. 即使父元素创建了 BFC，也无法包含绝对定位子元素的高度

### 对比示例

已在文件中添加对比：
- 浮动元素：BFC 可以包含，高度被撑开
- 绝对定位：BFC 无法包含，高度仍然塌陷

### 解决方案

对于绝对定位导致的高度塌陷，需要：

```css
.par {
  position: relative; /* 作为绝对定位的定位父元素 */
  min-height: 200px; /* 或 height: 200px; 必须明确设置高度 */
}
```

或者移除子元素的绝对定位，改用其他布局方式（如浮动、flex 等）。
